# scrcpy-lan v4.1 升级文档

> 2026-08-27 · 上游 v4.0 → v4.1 · 分支 `v4.0-lan`（已强推到 fork `qiansekai/scrcpy`）
> 真机验证：Redmi M2012K11AC（alioth，Android 13，Magisk），192.168.1.19

## 1. 背景

本项目是 scrcpy 的 LAN 定制版：设备端常驻 mirror server（TCP 27183）+ root admin server（27184），
桌面端 / webui 通过局域网直连，无需 USB。本次把基线从上游 v4.0 升级到 v4.1，全部自研功能随迁。

### 自研功能清单（相对上游的差异面）

| 区域 | 功能 | 关键文件 |
|---|---|---|
| server | 常驻 tunnel 模式：`tunnel_forward=true tunnel_port=27183`、accept 超时跳过音频/控制、video 常驻循环 | `server/.../device/DesktopConnection.java` |
| server | AdminServer：root 管理通道 27184，shell exec / 装 APK / 文件 | `server/.../admin/AdminServer.java` |
| server | audioDup 控制消息：动态开关设备出声（**消息号 23**，上游 v4.1 的 SCAN_FILE 占了 22） | `ControlMessage/Reader/Controller.java`、`audio/AudioPlaybackCapture.java` |
| server | audio mode：`output`（默认，设备出声）与 `playback`（全局捕获+设备默认静音） | `lan/*.sh`、`audio/*.java` |
| server | 降权后保留 inet 组（3003），修复 MIUI paranoid-network 内核 socket EACCES | `Server.java` `dropRootPrivileges()` |
| lan | 设备端守护脚本（双进程 guard、指数退避、日志截断） | `lan/scrcpy-lan-daemon.sh`、`lan/scrcpy-lan.sh`、`lan/autostart.sh` |
| 客户端 | `--no-adb`：直连 `--tunnel-host:--tunnel-port`，不初始化/销毁 adb | `app/src/cli.c`、`app/src/server.c`、`app/src/scrcpy.c` |
| webui | Go 中控：8080 web + 27182 原生代理；触控/键盘/剪贴板/audioDup | `webui/` |

## 2. 代码升级（rebase）

- 工作分支 `v4.0-lan` 共 **48 个自定义提交**，`git rebase v4.1` 重放，仅 **2 个提交产生冲突**：

### 冲突一：客户端 LAN 直连补丁（a6f82336）

上游 v4.1 给 `sc_file_pusher_init()` 增加了 `&s->controller` 参数（推送后触发 MediaStore 扫描），
与我们的 `!options->no_adb` 条件在同一行。合并结果：

```c
if (options->window && options->control && !options->no_adb) {
    if (!sc_file_pusher_init(&s->file_pusher, &s->controller, serial,
                             options->push_target)) {
```

### 冲突二：控制消息号撞车（d9ae44b7）

上游 v4.1 新增 `TYPE_SCAN_FILE = 22`，我们自研的 `TYPE_AUDIO_DUP` 也是 22。
**解决：AUDIO_DUP 改号 23**，三处同步：

- `server/.../control/ControlMessage.java`：`TYPE_AUDIO_DUP = 23`（与上游 SCAN_FILE=22 共存）
- `server/.../control/ControlMessageReader.java` / `Controller.java`：两条 case 并列
- `webui/internal/control/writer.go`：`TypeAudioDup = 23`

### 版本串适配

server 的 `Options.parse()` 要求启动参数中的 client version == `BuildConfig.VERSION_NAME`（v4.1），
所以 `lan/scrcpy-lan-daemon.sh`、`lan/scrcpy-lan.sh` 里的版本参数 **4.0 → 4.1**。

## 3. Windows 构建环境重建

本机 msys64（`D:\Kita-Tools\DevEnv\msys64`）的 ucrt64 运行时库和工具链曾被清空，本次全部重建：

### pacman

- 密钥环损坏（pacman-key 报错）→ 使用独立配置 `SigLevel = Never`（临时文件，用完即删）
- 国内镜像：TUNA / USTC / NJU；**msys 仓库路径必须用 `$arch`**（`/msys2/msys/$arch/`，用 `$repo` 会 404）
- 安装：`mingw-w64-ucrt-x86_64-{gcc,meson,ninja,pkgconf,cmake,nasm}`、`msys/{make,autoconf,automake,libtool}`（perl/wget/tar 自带）

### 前缀工具

dav1d / SDL / 项目 `cross_win64.txt` 引用 `x86_64-w64-mingw32-*` 前缀名，MSYS2 只提供无前缀版，
需在 `/ucrt64/bin` 建符号链接：`ar strip windres ranlib nm dlltool objdump as addr2line pkg-config`。
**`as` 尤其重要**：dlltool 通过符号链接调用时会按自己名字找 `x86_64-w64-mingw32-as`，
找不到则 CreateProcess 失败（错误被 make 忽略）→ 生成 **0 字节 .lib** → 后续链接全部崩。

### shasum

deps 脚本用 `shasum -a256 -c`，msys 只有 `sha256sum`，写了一个 shim 到 `/usr/bin/shasum`（剥掉 `-a256`）。

### 坑：系统 FFmpeg 污染交叉链接

曾为旧 v4.0 客户端安装 pacman 版 `mingw-w64-ucrt-x86_64-ffmpeg`（9.0.1，soname 63 系）。
它留在 sysroot 里的静态库会被 FFmpeg 8.1 交叉链接误抓 → undefined vaapi/vulkan 符号。
**必须卸载**（旧 v4.0 客户端已废弃，不再需要 63 系 DLL）。

## 5. 设备部署

```bash
# 推文件
adb push server/build/outputs/apk/release/server-release-unsigned.apk /data/local/tmp/scrcpy-lan-server.jar
adb push lan/scrcpy-lan-daemon.sh /data/local/tmp/
adb push lan/scrcpy-lan.sh       /data/local/tmp/
adb shell "su -c 'chmod 755 /data/local/tmp/scrcpy-lan-*.sh'"

# 启动守护（root）
adb shell "su -c 'nohup sh /data/local/tmp/scrcpy-lan-daemon.sh 27183 output 27184 \
  >/data/local/tmp/scrcpy-lan-daemon.log 2>&1 &'"

# 开机自启（Magisk/KernelSU）
adb push lan/autostart.sh /data/local/tmp/autostart.sh
adb shell "su -c 'cp /data/local/tmp/autostart.sh /data/adb/service.d/scrcpy-lan.sh; \
  chmod 755 /data/adb/service.d/scrcpy-lan.sh'"
```

- 端口：**27183** 镜像（video/audio/control 三路流）、**27184** root 管理
- audio mode 第二参数：`output`（默认）/ `playback`（配合 audioDup 控制设备出声）
- **注意：会话进行中 27183 不显示 LISTEN 是设计行为**——server 接完三路流即关闭监听，
  守护进程靠 `ps` 检查进程存活，不要误判为掉线（查 ESTABLISHED 连接确认会话）

## 6. 桌面端使用

```powershell
# 本项目客户端（纯局域网直连，不依赖 adb）
build-win-v4.1\dist\scrcpy.exe --no-adb --tunnel-host 192.168.1.19 --tunnel-port 27183

# webui 代理路径（webui.exe 运行时）：--tunnel-host 127.0.0.1 --tunnel-port 27182
```

官方客户端（如 `scrcpy-win64-v4.1`）不带 `--no-adb`，`--tunnel-host/--tunnel-port` 会自动启用
adb forward 并推一个 stock server（bind 27183 失败后闲置，会干扰 daemon guard 的 ps 判定），
推荐始终使用本项目客户端。
